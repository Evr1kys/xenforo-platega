# Platega для XenForo 1.5

Оплата разовых повышений пользователей в RUB. Автор: [Evrik (Evr1kys)](https://github.com/Evr1kys). Лицензия MIT.

Это отдельный модуль для архитектуры XenForo 1.x. Проверен на XenForo 1.5.24 с PHP 7.4 и MariaDB 10.11. Для других выпусков 1.x совместимость пока не подтверждена. Модуль требует PHP 7.4+ и cURL; версия PHP должна также поддерживаться самим форумом.

## Установка

1. Скопируйте содержимое upload в корень форума.
2. Импортируйте addon-EvrikPlategaLegacy.xml через управление дополнениями.
3. Добавьте в library/config.php настройки магазина:

       $config['evrikPlatega'] = [
           'merchant_id' => 'UUID вашего магазина',
           'secret' => 'Секретный ключ'
       ];

4. В кабинете Platega укажите callback: https://forum.example/platega_callback.php с учётом подкаталога форума.
5. Создайте повышение пользователя в RUB, отключите повторяющуюся оплату.
6. Откройте **Повышения учётной записи → Оплата через Platega**. Прямой маршрут — index.php?account/platega.

Адрес форума в настройках должен использовать HTTPS. Ключ хранится только в конфигурации сервера. Не добавляйте его в Git и не передавайте в URL.

Для RUB на стандартной странице повышений показывается кнопка Platega; форма PayPal сохраняется для других валют. Модуль добавляет RUB в форму редактирования повышений.

## Обработка платежей

Уведомление проверяется по Merchant ID и Secret, затем модуль запрашивает транзакцию через API и сверяет сумму, валюту и ключ покупки. Получение уведомления само по себе не выдаёт повышение.

Повторный запрос создания открывает ту же платёжную ссылку. После сетевой ошибки автоматического повтора POST нет: неизвестно, успел ли шлюз создать транзакцию.

Для восстановления платежа используйте ключ из таблицы xf_evrik_platega_legacy и ID транзакции из кабинета:

    php platega_reconcile.php REQUEST_KEY TRANSACTION_ID

Команда работает только в CLI. Для уже привязанного платежа ID можно не указывать.

Возврат отзывает только повышение, выданное соответствующей покупкой. Если срок повышения изменён другим платежом или администратором, автоматический отзыв блокируется: необходимо вручную проверить права пользователя. Оплаченная покупка не становится неоплаченной из-за запоздалого PENDING или CANCELED; подтверждение после возврата не восстанавливает доступ.

## Ограничения

- Только стандартные повышения, разовые платежи и RUB.
- Нет подписок, выплат и создания возврата из форума.
- Проверки используют тестовые ответы API; полный цикл с магазином Platega не подтверждён.
- Удаление дополнения удаляет его журнал операций. Не удаляйте модуль, пока есть незавершённые платежи.
- Исходники XenForo не входят в пакет.

## Проверка на тестовом форуме

    php tests/xenforo1.php /path/to/forum --disposable-database

Скрипт находится в репозитории. Он создаёт пользователей и повышения: используйте отдельную тестовую базу. Проверяет штатную выдачу/отзыв группы, повторные и запоздалые уведомления, подмену суммы, ошибку авторизации, неопределённый результат создания, XML-регистрацию и компиляцию шаблона.
