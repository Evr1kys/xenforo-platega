На обеих версиях проверены обновления Beta 2 → Beta 3 → 1.0.0. Новые проверки подтверждают наличие индексов, совместную работу фильтров и поиска, пагинацию и заполнение формы без запроса к платёжному API. Удаление и повторная установка из ZIP ранее проверялись для Beta 2.

Интеграционные проверки используют настоящие классы XenForo и отдельные базы данных. Сетевые ответы Platega подменены тестовым клиентом; реальная оплата не выполняется.

Проверяются:

- Регистрация провайдера, сохранение профиля и компиляция административного шаблона.
- Создание платежа и повторное открытие без второй транзакции.
- Проверка ключа, суммы, валюты и привязки транзакции к покупке.
- Фактическая выдача и отзыв стандартного повышения пользователя.
- Повторные и запоздалые уведомления.
- Два параллельных процесса обработки одного платежа: одна выдача покупки.
- Откат транзакции базы при исключении в обработчике покупки и успешный повтор.
- Восстановление связи с транзакцией после неопределённого результата создания.
- Отсутствие ключа в журнале платежей.
- Ручное восстановление оплаты и возврата, повторная проверка и подмена транзакции.
- Отрисовка страниц админки, наличие CSRF-токенов, запрет GET для обработки и право управления платежами.
- Обновление Beta 1 → Beta 2 с сохранением таблицы и профилей.

## Запуск

Без XenForo:

```sh
php tests/protocol.php
python3 scripts/check-package.py
python3 scripts/build.py
python3 scripts/check-archive.py
```

Проверка воспроизводимости:

```sh
python3 scripts/build.py
sha256sum dist/Evrik-Platega-*.zip
python3 scripts/build.py
sha256sum dist/Evrik-Platega-*.zip
```

Обе контрольные суммы должны совпасть.

С собственной лицензированной копией XenForo:

1. Установите чистый тестовый форум с отдельной базой и пользователем с ID 1.
2. Отключите отправку почты (`$config['enableMail'] = false`). Укажите HTTPS-адрес форума.
3. Установите дополнение из собранного ZIP.
4. Выполните:

```sh
php tests/xenforo.php /path/to/test/forum --disposable-database
```

Тест создаёт платёжные профили, повышения и покупки, меняет повышение пользователя с ID 1. Запускайте его только на одноразовой тестовой базе. Внешние запросы оплаты заменены тестовым клиентом. Для проверки параллельных уведомлений нужен `proc_open`.

Успех обозначается строкой `OK: XenForo ...`. Один код завершения PHP недостаточен: обработчик исключений XenForo может завершить процесс с кодом 0.

## CI и релизы

GitHub Actions проверяет синтаксис и протокол на PHP 7.4–8.5, XML, версии данных, ссылки на фразы, структуру пакета, сборку и содержимое ZIP. Исходники XenForo не распространяются, поэтому интеграционные проверки в публичный CI не включены.

При изменении версии в основной ветке workflow повторяет проверки и воспроизводимую сборку, создаёт тег из `addon.json` и публикует релиз с ZIP и SHA-256. Для версий с пометкой Beta выставляется статус предварительного выпуска. Уже опубликованные релизы не перезаписываются.

## До рабочего запуска

Нужна контрольная оплата с ключами конкретного магазина, доставка уведомления через его HTTPS/WAF и проверка возврата. Доступность каждого способа зависит от договора и настроек Platega.

Блокировка строки защищает изменения в одной базе InnoDB. Побочные эффекты сторонних обработчиков (например, отправка данных во внешний сервис) должны иметь собственную защиту от повторов. Стандартная отправка квитанции XenForo происходит внутри обработчика; доставка почты не является частью транзакции базы.
