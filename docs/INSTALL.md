# Установка и настройка

## Перед установкой

Сделайте резервную копию файлов и базы форума. Нужны HTTPS, доступ PHP к `https://app.platega.io` и действующие ключи магазина Platega. Способы оплаты подключаются на стороне Platega; наличие пункта в настройках не активирует его у провайдера.

Дополнение передаёт в Platega стоимость, валюту, название покупки, случайный ключ покупки, ссылки возврата, ID и имя пользователя форума (`metadata.userId`, `metadata.userName`). Учитывайте это в информации об обработке данных пользователей.

## Установка

Скачайте установочный ZIP из [Releases](https://github.com/Evr1kys/xenforo-platega/releases). Установите через раздел дополнений XenForo либо загрузите содержимое папки `upload` в корень форума и нажмите «Установить» у Platega payments.

Через командную строку после загрузки файлов:

```sh
php cmd.php xf:addon-install Evrik/Platega
```

## Платёжный профиль

Откройте **Настройки → Платёжные профили → Добавить платёжный профиль → Platega**.

| Поле | Что указать |
| --- | --- |
| Merchant ID | UUID магазина из кабинета Platega |
| Secret key | Секретный ключ этого магазина |
| Способ оплаты | Выбор на странице Platega или один из подключённых способов |
| URL уведомлений | Скопировать в кабинет Platega |

Пример URL для форума в корне домена:

```text
https://forum.example.com/payment_callback.php?_xfProvider=evrikPlatega
```

Для форума в подпапке URL содержит эту подпапку. Копируйте адрес из профиля, а не составляйте его вручную. Не удаляйте параметр `_xfProvider`.

На стороне Platega откройте **Настройки → Callback URLs** и сохраните адрес. CDN/WAF не должен показывать CAPTCHA на этом пути. Прокси должен передавать заголовки `X-MerchantId` и `X-Secret` без изменения.

Ключ хранится в `xf_payment_profile.options` по стандартной схеме XenForo. Ограничьте доступ к платёжным профилям и резервным копиям базы. После смены ключа обновите профиль форума.

## Покупки

В настройках платного повышения пользователя включите профиль Platega, задайте цену в RUB и отключите автоматическое продление. Срок действия повышения может быть ограниченным: пользователь покупает его один раз и при необходимости продлевает новой покупкой.

В сторонних дополнениях выбирайте профиль Platega в их настройках оплаты. Совместимость зависит от использования стандартного XenForo Purchasable API.

`$config['enableLivePayments']` должен быть включён. При отключённом параметре создание платежей блокируется: дополнение не имитирует тестовую оплату и не переключается автоматически на реальные списания.

## Контрольная оплата

1. Создайте тестовое повышение с небольшой суммой, допустимой для вашего магазина.
2. Оплатите его обычным пользователем.
3. Убедитесь, что после уведомления выданы нужные права, а в журнале платежей появилась запись.
4. Повторная доставка того же уведомления не должна продлевать повышение второй раз.
5. При необходимости выполните возврат в кабинете Platega и проверьте отзыв покупки.

Возвращение браузера на форум само по себе ничего не выдаёт. Если уведомление ещё не пришло, обновите страницу позже.

## Если платёж не создался

При таймауте нельзя считать, что транзакция отсутствует: Platega мог создать её до обрыва связи. Дополнение записывает состояние `UNCERTAIN` и блокирует повторное создание для того же ключа покупки. Сбой процесса до сохранения ответа может оставить `CREATING`.

Проверьте кабинет Platega по `orderId` / `payload` — это ключ покупки из сообщения в журнале ошибок. Если транзакция существует, не создавайте повторную оплату. Доставка корректного уведомления с `payload` позволяет восстановить связь для `UNCERTAIN`; для зависшего `CREATING` обработка возможна после 60 секунд. После проверки администратор может запросить повторную доставку уведомления у Platega. Автоматического фонового опроса в этой версии нет.

Если Platega подтвердил отсутствие транзакции, начните новую покупку. Старую запись не нужно удалять. Удаление записи с уже оплаченным платежом нарушит защиту от повторной обработки.

## Коды ответа на уведомления

| Код | Причина / действие |
| --- | --- |
| 200 | Событие обработано либо уже было обработано |
| 403 | Неверные ключи или данные платежа; проверьте профиль и журнал |
| 404 | XenForo не нашёл покупку, пользователя или обработчик товара |
| 503 | Платёж ещё создаётся, API временно недоступен или статус ещё PENDING; нужна повторная доставка |
| 500 | Ошибка выдачи покупки; проверьте журнал сервера и повторите доставку после исправления |

Platega описывает до трёх повторных попыток с интервалом пять минут. Если они закончились, после устранения причины запросите повторную доставку через поддержку Platega. Не выдавайте доступ по скриншоту оплаты или по одному лишь возврату браузера.

## Обновление и удаление

Обновляйте через ZIP нового релиза. Перед удалением отключите профиль для новых покупок, разберите незавершённые платежи и сохраните резервную копию. Удаление дополнения удаляет его таблицу транзакций; история стандартного журнала XenForo сохраняется. После удаления уведомления больше не обрабатываются. Переустановка не восстанавливает защиту от повторной обработки старых платежей.

## API

Реализация сверена с [документацией Platega](https://docs.platega.io/llms.txt) 15 сентября 2026 года:

- `POST /v2/transaction/process` — выбор способа на платёжной странице.
- `POST /transaction/process` — фиксированный способ.
- `GET /transaction/{id}` — проверка транзакции перед выдачей/отзывом покупки.
- Уведомления с `X-MerchantId`, `X-Secret`, статусами `CONFIRMED`, `CANCELED`, `CHARGEBACKED`.

В документации схемы callback перечислены не все статусы: `CHARGEBACKED` указан в описании. Он поддерживается дополнением и проверяется повторным запросом состояния через API.
